- [o] S7 — P1, follow-up of S5: The group marks the upstream files that are executable. Input: the release build extracts the tarball without the header modes, so an upstream file whose tar header mode has an execute bit (such as `skills/brainstorming/scripts/run.sh`) reaches the agents import as a text entry without it, and the import writes it without the execute bit. Expected: the build extracts with the header modes (`tar -xzp`), which the umask of the build does not change; each `files` entry whose upstream file has an execute bit carries `executable: true`, and the other entries carry no member; `groupFrom` passes the member through and refuses a value that is not a boolean. Red: `node --test test/` failed two cases before the change: the build marked no file, and `groupFrom` dropped the member. The case without an execute bit passed before the change, as a guard. Result: the build extracts with `tar -xzpf` and marks each entry whose header mode has an execute bit, `groupFrom` passes the member through and refuses a value that is not a boolean, and `node --test test/` passes its 34 tests. Without `-p`, a restrictive umask clears the execute bit of an extracted file, and the test that marks a file runs the build under umask 077.
